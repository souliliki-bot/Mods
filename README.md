# Обман и доверие (Leave or Steal)

**Minecraft Java 1.21.1 · Fabric · Java 21**

## Текущая реализация

Проект содержит исходный Fabric-мод и CI-сборку. На сервере доступны команды:

- `/leaveorsteal help` — справка.
- `/leaveorsteal settings` — интерактивное меню настроек (требуются права оператора).
- `/leaveorsteal join` — встать в очередь на матч 1 на 1.
- `/leaveorsteal status` — состояние матча и роль.
- `/leaveorsteal loot` — показать только свои выигранные предметы до конца матча.
- `/leaveorsteal claim <текст>` — заявление владельца о тайном предмете.
- `/leaveorsteal keep` — оставить предмет владельцу.
- `/leaveorsteal steal` — забрать предмет себе.
- `/leaveorsteal leave` — покинуть очередь/матч или сдаться в финальной дуэли.
- `/leaveorsteal setarena1` — сохранить точку появления первого участника (права оператора).
- `/leaveorsteal setarena2` — сохранить точку появления второго участника (права оператора).
- `/leaveorsteal setting arena|health|hunger` — переключить параметр (команда используется кнопками меню; требуются права оператора).
- `/leaveorsteal class <имя_класса>` — включить/выключить класс предметов в матчах (оператор; доступны подсказки имён классов).
- `/leaveorsteal weight <имя_класса> <0..100000>` — задать вес выпадения класса (оператор).
- `/leaveorsteal classes` — семь классов предметов.
- `/leaveorsteal pool` — количество предметов в каждом пуле.
- `/leaveorsteal items <namespace>` — число предметов указанного мода.
- `/leaveorsteal inspect <namespace:item>` — показать класс предмета и источник правила классификации (оператор).
- `/leaveorsteal reloadconfig` — перезагрузить конфигурацию (требуется уровень прав 2).

## Сохранение наград

- При отключении игрока незавершённый матч завершается, а накопленные награды сохраняются для отсутствующего игрока.
- При штатной остановке сервера незавершённые матчи переводятся в очередь наград; предмет текущего раунда также сохраняется за текущим владельцем.
- Награды записываются в `data/leave-or-steal-rewards.json` и автоматически выдаются игроку при следующем входе. Для сериализации используется registry-aware `ItemStack.CODEC` вместе с данными реестров мира: это позволяет сохранять стандартные и модовые компоненты предметов, а не только ID и количество. Если предмет не удаётся сериализовать, новый файл не заменяет предыдущий — ошибка записывается в лог.
- При заполненном инвентаре остаток предметов выбрасывается рядом с игроком.

Сохранение выполняется при штатной остановке сервера; аварийное завершение процесса не гарантирует сохранность последних изменений.

## Предметы и конфигурация

Список предметов берётся из реестра сервера, включая зарегистрированные предметы установленных модов. При первом запуске создаётся файл `config/leave-or-steal.properties`.

Поддерживаются:
- включение/отключение классов предметов через меню настроек или `/leaveorsteal class <имя_класса>`; состояние хранится в `enabledClasses`;
- включение namespace через `enabledNamespaces` (или `*` для всех);
- исключение namespace через `excludedNamespaces`;
- исключение отдельных ID через `excludedItems`;
- исключение предметов по фрагментам ID через `excludedPathKeywords` (по умолчанию исключаются яйца призыва, командные блоки, барьеры, структурные блоки, джигсо-блоки, отладочная палка и книга знаний);
- ручное назначение класса через ключи вида `item.minecraft:diamond_sword=DIAMOND_GEAR`.

Автоматическая классификация распознаёт распространённые названия еды, зелий, оружия, инструментов и брони. Незеритовый, алмазный и железный классы назначаются только предметам, похожим на снаряжение; неизвестные модовые предметы остаются в `COMMON`. Исключения namespace/ID и фильтр `excludedPathKeywords` применяются до классификации и имеют приоритет над ручным назначением класса.

### API интеграций Fabric

Другой мод может подключить собственные правила без зависимости от исходников Leave or Steal. Для этого он объявляет entrypoint в своём `fabric.mod.json`:

```json
{
  "entrypoints": {
    "leave_or_steal:item_classifiers": [
      "example.mod.ExampleItemClassifier"
    ]
  }
}
```

Класс должен реализовать публичный интерфейс `ItemClassificationProvider` из нашего мода:

```java
public final class ExampleItemClassifier implements ItemClassificationProvider {
    @Override
    public void register(ItemClassificationRegistry registry) {
        registry.registerItem(
            Identifier.of("example", "ruby_sword"),
            ChestClass.RARE
        );

        registry.registerNamespace("example", id -> {
            if (id.getPath().contains("ruby")) return ChestClass.RARE;
            return null; // передать предмет встроенной классификации
        });
    }
}
```

Правила конкретного предмета имеют приоритет над правилами namespace. Если несколько интеграций зарегистрировали классификаторы для одного namespace, они проверяются в порядке регистрации: первый вернувший класс (не `null`) определяет результат. Если разные интеграции назначили разные классы одному конкретному ID, действует последняя регистрация, а конфликт записывается в серверный лог. Если классификатор вернул `null` или выбросил исключение, проверяется следующий. Если ни один не подошёл, используется встроенная классификация. Ручное назначение через конфиг Leave or Steal имеет приоритет над интеграциями. Исключения namespace, ID и фрагментов пути применяются раньше всех правил. Интеграции повторно регистрируются командой `/leaveorsteal reloadconfig`.

В раундах сервер выбирает предмет из доступных пулов. Его название и категория видны только текущему владельцу; соперник получает только заявление владельца. После решения предмет сохраняется за победителем раунда и выдаётся в инвентарь после девятого раунда.

После девяти раундов матч переходит в фазу финальной PvP-дуэли. Победитель определяется по смерти соперника; отключение или команда `/leave` во время дуэли засчитываются как сдача. Для боя на сервере должно быть включено PvP (`pvp=true` в `server.properties`). Администратор может встать в нужные места и выполнить `/leaveorsteal setarena1` и `/leaveorsteal setarena2`; точки и измерения сохраняются в `data/leave-or-steal-arena.json` мира. После девятого раунда участники автоматически телепортируются на эти позиции. Если точки не настроены, дуэль начинается на текущих местах. Перед дуэлью обоим игрокам восстанавливаются здоровье и сытость. Инвентарь, броня и активные эффекты не сбрасываются и не заменяются.

## Меню настроек

Оператор может открыть отдельное экранное меню клавишей `O` или командой `/leaveorsteal settings`. В нём доступны телепортация на настроенную арену, восстановление здоровья и восстановление голода перед финальной дуэлью, включение и отключение семи классов предметов, а также изменение веса выпадения каждого класса кнопками `−` и `+`. Значения весов синхронизируются с сервером; изменения сохраняются в `config/leave-or-steal.properties`. Для экранного GUI мод должен быть установлен и на клиенте, и на сервере. Если клиентского мода нет, команда `/leaveorsteal settings` сохраняет чат-меню с кликабельными переключателями.

## Что ещё не реализовано

- Физические комнаты с разделительным стеклом.
- Автоматическое строительство арены.
- Бот и три уровня сложности.
- Таймеры раундов и полноценная обработка отключения с сохранением уже выигранных предметов.
- Голосовой чат.

Это ранняя играбельная основа для проверки механики через команды, а не законченная мини-игра. Перед использованием на публичном сервере требуется тестирование.


### Дополнительные правила классификации

В `config/leave-or-steal.properties` можно задать `namespace.magicmod=RARE`, чтобы отнести все предметы namespace `magicmod` к классу `RARE`. Также можно задать `path.LEGENDARY=ruby,ancient,artifact`: совпадение фрагмента в ID предмета назначит указанный класс. Приоритет: ручной ID, правила интеграций, namespace из конфига, фрагменты пути, встроенная классификация. Исключения применяются раньше классификации. После изменения файла выполните `/leaveorsteal reloadconfig`.


### Вероятности выпадения классов

Шанс выбирается по весам классов, а затем случайный предмет выбирается равновероятно внутри выбранного класса. Значения — относительные веса; если пул класса пуст, его вес не учитывается, а остальные вероятности автоматически нормализуются.

По умолчанию:

| Класс | Вес |
|---|---:|
| COMMON | 60 |
| IRON_GEAR | 20 |
| DIAMOND_GEAR | 8 |
| NETHERITE_GEAR | 2 |
| POTIONS_FOOD | 5 |
| RARE | 4 |
| LEGENDARY | 1 |

Измени в `config/leave-or-steal.properties` параметры `weight.<КЛАСС>`, например `weight.LEGENDARY=0` полностью убирает легендарные предметы из случайного выбора, не отключая сам класс. Нулевые и отрицательные значения не дают классу выпадать; некорректное число заменяется весом по умолчанию. После правки выполни `/leaveorsteal reloadconfig`. Вес также можно менять прямо в экранном меню клавишей `O` или через `/leaveorsteal settings`: кнопки `−` и `+` уменьшают или увеличивают его на единицу. В чат-меню для клиентов без мода доступны кликабельные кнопки изменения веса. Команда `/leaveorsteal weight LEGENDARY 0` задаёт точное значение. Изменения сохраняются автоматически.
