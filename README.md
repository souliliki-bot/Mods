# Обман и доверие (Leave or Steal)

**Minecraft Java 1.21.1 · Fabric · Java 21**

## Текущая реализация

## Арена

Матч сразу переносит участников на арену: первый игрок появляется в точке 1, второй игрок — в точке 2. В одиночном режиме игрок появляется в точке 1, а моб-соперник после раундов — в точке 2. Все раунды и финальный бой проходят там же.

Оператор должен один раз настроить точки, стоя на нужных местах:
1. `/leaveorsteal setarena1` — позиция первого игрока.
2. `/leaveorsteal setarena2` — позиция второго игрока или моба.

Точки и измерения сохраняются в `world/data/leave-or-steal-arena.json`. Переключатель «Телепортация на арену» в настройках должен быть включён. Если точки не заданы или переключатель выключен, матч останется на месте запуска и сообщит об этом.


Проект содержит исходный Fabric-мод и CI-сборку. На сервере доступны команды:

- `/leaveorsteal help` — справка.
- `/leaveorsteal menu` — открыть меню лобби.
- `/leaveorsteal lobby create` — создать приватное лобби.
- `/leaveorsteal invite <игрок>` — пригласить игрока, который сейчас на сервере.
- `/leaveorsteal accept <создатель>` и `/leaveorsteal decline <создатель>` — принять или отклонить приглашение.
- `/leaveorsteal bot` — обычный одиночный матч против ИИ и финального моба.
- `/leaveorsteal quick` — быстрый матч против ИИ на 3 раунда.
- `/leaveorsteal chaos` — безумный матч на 9 раундов с повышенной частотой случайных событий.
- `/leaveorsteal highstakes` — матч на 9 раундов с удвоенными наградами.
- `/leaveorsteal ability shield|insight` — одноразовая способность за матч: щит владельца отменяет кражу текущего предмета, прозрение позволяет выбирающему узнать предмет.
- `/leaveorsteal wager` — поставить предмет из основной руки во время раунда; победитель решения получает все ставки раунда.
- `/leaveorsteal stats` — показать победы, поражения и титул.
- `/leaveorsteal settings` — интерактивное меню настроек (требуются права оператора).
- `/leaveorsteal join` — встать в очередь на матч 1 на 1.
- `/leaveorsteal status` — состояние матча и роль.
- `/leaveorsteal loot` — показать только свои выигранные предметы до конца матча.
- `/leaveorsteal claim <текст>` — заявление владельца о тайном предмете.
- `/leaveorsteal keep` — оставить предмет владельцу.
- `/leaveorsteal steal` — забрать предмет себе.
- `/leaveorsteal leave` — покинуть очередь/матч или сдаться в финальной дуэли.
- `/leaveorsteal setarena1` — сохранить точку появления первого участника (права оператора).
- `/leaveorsteal setarena2` — сохранить точку появления второго участника (права оператора).
- `/leaveorsteal setting arena|health|hunger` — переключить параметр (команда используется кнопками меню; требуются права оператора).
- `/leaveorsteal rounds <1..30>` — установить количество раундов в следующих матчах (по умолчанию 9; оператор).
- `/leaveorsteal class <имя_класса>` — включить/выключить класс предметов в матчах (оператор; доступны подсказки имён классов).
- `/leaveorsteal weight <имя_класса> <0..100000>` — задать вес выпадения класса (оператор).
- `/leaveorsteal classes` — семь классов предметов.
- `/leaveorsteal pool` — количество предметов в каждом пуле.
- `/leaveorsteal items <namespace>` — число предметов указанного мода.
- `/leaveorsteal inspect <namespace:item>` — показать класс предмета и источник правила классификации (оператор).
- `/leaveorsteal reloadconfig` — перезагрузить конфигурацию (требуется уровень прав 2).

## Сохранение наград

- При отключении игрока незавершённый матч завершается, а накопленные награды сохраняются для отсутствующего игрока.
- При штатной остановке сервера незавершённые матчи переводятся в очередь наград; предмет текущего раунда также сохраняется за текущим владельцем.
- Награды записываются в `data/leave-or-steal-rewards.json` и автоматически выдаются игроку при следующем входе. Для сериализации используется registry-aware `ItemStack.CODEC` вместе с данными реестров мира: это позволяет сохранять стандартные и модовые компоненты предметов, а не только ID и количество. Если предмет не удаётся сериализовать, новый файл не заменяет предыдущий — ошибка записывается в лог.
- При заполненном инвентаре остаток предметов выбрасывается рядом с игроком.

Сохранение выполняется при штатной остановке сервера; аварийное завершение процесса не гарантирует сохранность последних изменений.

## Предметы и конфигурация

Список предметов берётся из реестра сервера, включая зарегистрированные предметы установленных модов. При первом запуске создаётся файл `config/leave-or-steal.properties`.

Поддерживаются:
- включение/отключение классов предметов через меню настроек или `/leaveorsteal class <имя_класса>`; состояние хранится в `enabledClasses`;
- включение namespace через `enabledNamespaces` (или `*` для всех);
- исключение namespace через `excludedNamespaces`;
- исключение отдельных ID через `excludedItems`;
- исключение предметов по фрагментам ID через `excludedPathKeywords`; кроме того, декоративные `BlockItem` (ступени, плиты, заборы, двери, ковры, баннеры, факелы, фонари, цветы, стекло, шерсть, бетон, терракота и другие декоративные блоки) автоматически исключаются из всех пулов и не могут выпасть наградой;
- ручное назначение класса через ключи вида `item.minecraft:diamond_sword=DIAMOND_GEAR`.
- выдача подходящих боеприпасов вместе с оружием через правила `ammo.<namespace:оружие>=<namespace:боеприпас>,<количество>`. По умолчанию лук и арбалет получают по 16 стрел. Для модового оружия добавь, например, `ammo.gunmod:rifle=gunmod:rifle_bullet,24`. Боеприпасы выдаются тому же игроку, которому досталось оружие, и не выпадают отдельным случайным предметом.

Автоматическая классификация распознаёт распространённые названия еды, зелий, оружия, инструментов и брони. Незеритовый, алмазный и железный классы назначаются только предметам, похожим на снаряжение; неизвестные модовые предметы остаются в `COMMON`. Исключения namespace/ID и фильтр `excludedPathKeywords` применяются до классификации и имеют приоритет над ручным назначением класса.

### API интеграций Fabric

Другой мод может подключить собственные правила без зависимости от исходников Leave or Steal. Для этого он объявляет entrypoint в своём `fabric.mod.json`:

```json
{
  "entrypoints": {
    "leave_or_steal:item_classifiers": [
      "example.mod.ExampleItemClassifier"
    ]
  }
}
```

Класс должен реализовать публичный интерфейс `ItemClassificationProvider` из нашего мода:

```java
public final class ExampleItemClassifier implements ItemClassificationProvider {
    @Override
    public void register(ItemClassificationRegistry registry) {
        registry.registerItem(
            Identifier.of("example", "ruby_sword"),
            ChestClass.RARE
        );

        registry.registerNamespace("example", id -> {
            if (id.getPath().contains("ruby")) return ChestClass.RARE;
            return null; // передать предмет встроенной классификации
        });
    }
}
```

Правила конкретного предмета имеют приоритет над правилами namespace. Если несколько интеграций зарегистрировали классификаторы для одного namespace, они проверяются в порядке регистрации: первый вернувший класс (не `null`) определяет результат. Если разные интеграции назначили разные классы одному конкретному ID, действует последняя регистрация, а конфликт записывается в серверный лог. Если классификатор вернул `null` или выбросил исключение, проверяется следующий. Если ни один не подошёл, используется встроенная классификация. Ручное назначение через конфиг Leave or Steal имеет приоритет над интеграциями. Исключения namespace, ID и фрагментов пути применяются раньше всех правил. Интеграции повторно регистрируются командой `/leaveorsteal reloadconfig`.

В раундах сервер выбирает предмет из доступных пулов. Его название и категория видны только текущему владельцу; соперник получает только заявление владельца и кликабельные кнопки «Украсть» / «Оставить» в чате. В режимах с событиями возможны двойная награда, ловушка с отравлением победителя и раскрытие предмета. «Безумный режим» повышает вероятность событий, «Высокие ставки» удваивают награду. Одноразовый «Щит» защищает предмет от кражи, а «Прозрение» раскрывает предмет выбирающему. Команда `/leaveorsteal wager` забирает предмет из основной руки в ставку раунда; победитель получает ставки вместе с наградой. При прерывании матча или остановке сервера залог возвращается владельцу. В PvP-матчах первый выбирающий чередуется между играми: в первой игре это первый участник пары, во второй — второй; очередность сохраняется в настройках мира. После решения предмет сохраняется за победителем раунда и выдаётся в инвентарь после девятого раунда.

После раундов обычный матч переходит в финальную PvP-дуэль игроков. В одиночном режиме на арену выходит случайный враждебный моб из группы MONSTER, выбранный из реестра сущностей сервера (в том числе добавленный другими модами); он усилен эффектами силы и сопротивления. До начала боя моб ждёт взаимодействия: нажми по нему правой кнопкой мыши и выбери «Уйти» или «Сразиться». При выборе боя моб начинает атаковать; при уходе матч завершается поражением игрока. Моб получает выигранные им за раунды предметы: лучшую найденную экипируемую броню надевает, а подходящее оружие берёт в основную руку. Экипированные предметы гарантированно выпадают после его смерти. Игрок побеждает при смерти моба, а смерть игрока или сдача засчитывается как поражение. Обычная PvP-дуэль игроков определяется по смерти соперника; отключение или команда `/leave` во время дуэли засчитываются как сдача. Для боя игроков на сервере должно быть включено PvP (`pvp=true` в `server.properties`). Администратор может встать в нужные места и выполнить `/leaveorsteal setarena1` и `/leaveorsteal setarena2`; точки и измерения сохраняются в `data/leave-or-steal-arena.json` мира. Если точки не настроены, бой с мобом начинается рядом с игроком. Перед боем игроку восстанавливаются здоровье и сытость. Инвентарь, броня и активные эффекты игрока не сбрасываются.

## Меню лобби и настройки

Любой игрок может открыть меню лобби клавишей `O` или командой `/leaveorsteal menu`. Кнопка «Создать лобби» создаёт приватную комнату на двух участников; затем можно выбрать любого свободного игрока онлайн и отправить ему приглашение. Приглашённый принимает или отклоняет его кликабельным сообщением в чате. После принятия сразу запускается матч между этими двумя игроками. В раундах после заявления соперника в чате появляются две кликабельные кнопки: «Украсть» и «Оставить» — отдельные команды вводить не нужно. Первый выбор в первой PvP-игре делает первый участник пары (создатель лобби или первый в очереди); в следующей игре первым выбирает второй участник. Чередование сохраняется между перезапусками сервера. Кнопка «Играть с ботом» запускает одиночный матч: виртуальный соперник чередуется с игроком как владелец предмета, формирует заявления и принимает решения о краже. В финале вместо симуляции появляется настоящий враждебный моб из реестра сущностей сервера; он сражается с игроком, используя добытое оружие и броню.

Оператор может открыть отдельное экранное меню настроек командой `/leaveorsteal settings`. В нём доступны телепортация на настроенную арену, восстановление здоровья и восстановление голода перед финальной дуэлью, настройка количества раундов (от 1 до 30, по умолчанию 9), включение и отключение семи классов предметов, а также изменение веса выпадения каждого класса кнопками `−` и `+`. Количество раундов можно менять кнопками `−`/`+` в меню или командой `/leaveorsteal rounds <число>`; значение сохраняется в `data/leave-or-steal-settings.json` и применяется к новым матчам. Значения весов синхронизируются с сервером; изменения сохраняются в `config/leave-or-steal.properties`. Для экранного GUI мод должен быть установлен и на клиенте, и на сервере. Если клиентского мода нет, команда `/leaveorsteal settings` сохраняет чат-меню с кликабельными переключателями.

## Что ещё не реализовано

- Физические комнаты с разделительным стеклом.
- Автоматическое строительство арены.
- Настройка сложности и поведения мобов-противников.
- Таймеры раундов и полноценная обработка отключения с сохранением уже выигранных предметов.
- Голосовой чат.

Это ранняя играбельная основа для проверки механики через команды, а не законченная мини-игра. Перед использованием на публичном сервере требуется тестирование.


### Дополнительные правила классификации

В `config/leave-or-steal.properties` можно задать `namespace.magicmod=RARE`, чтобы отнести все предметы namespace `magicmod` к классу `RARE`. Также можно задать `path.LEGENDARY=ruby,ancient,artifact`: совпадение фрагмента в ID предмета назначит указанный класс. Приоритет: ручной ID, правила интеграций, namespace из конфига, фрагменты пути, встроенная классификация. Исключения применяются раньше классификации. После изменения файла выполните `/leaveorsteal reloadconfig`.


### Вероятности выпадения классов

Шанс выбирается по весам классов, а затем случайный предмет выбирается равновероятно внутри выбранного класса. Значения — относительные веса; если пул класса пуст, его вес не учитывается, а остальные вероятности автоматически нормализуются.

По умолчанию:

| Класс | Вес |
|---|---:|
| COMMON | 60 |
| IRON_GEAR | 20 |
| DIAMOND_GEAR | 8 |
| NETHERITE_GEAR | 2 |
| POTIONS_FOOD | 5 |
| RARE | 4 |
| LEGENDARY | 1 |

Измени в `config/leave-or-steal.properties` параметры `weight.<КЛАСС>`, например `weight.LEGENDARY=0` полностью убирает легендарные предметы из случайного выбора, не отключая сам класс. Нулевые и отрицательные значения не дают классу выпадать; некорректное число заменяется весом по умолчанию. После правки выполни `/leaveorsteal reloadconfig`. Вес также можно менять прямо в экранном меню клавишей `O` или через `/leaveorsteal settings`: кнопки `−` и `+` уменьшают или увеличивают его на единицу. В чат-меню для клиентов без мода доступны кликабельные кнопки изменения веса. Команда `/leaveorsteal weight LEGENDARY 0` задаёт точное значение. Изменения сохраняются автоматически.
